# MoneyTown 모바일 투자 게임

가상 시장의 뉴스와 차트를 해석하고, 주식 거래로 얻은 자금을 정보와 다른 자산에 투자하는 **Unity 기반 Android 게임**입니다. 주 개발 프로젝트는 `unity/`이며 Unity 6.3 LTS와 C#을 사용합니다.

## 문서

- [게임 기획서](docs/game-design.md): 게임 규칙, 화면, 경제 구조와 초기 개발 범위
- [참고 자료 조사](docs/references.md): 유사 게임, 공식 출처와 적용 아이디어
- [개발 노트](docs/development-log.md): 개발 계획, 실제 변경, 검증과 다음 작업
- 참고 화면: `assets/reference-trading-screen.png`는 사용자가 제공한 내부 기획 참고용 이미지로, 로컬에만 보관합니다.

## Git 저장소와 기록

GitHub의 공개 [sanu1227/MoneyTown](https://github.com/sanu1227/MoneyTown) 저장소에서 관리합니다. 현재 개발 상태인 0.18.2를 첫 기준 커밋과 `v0.18.2` 태그로 기록합니다. 이전 버전별 작업과 검증 결과는 개발 노트에 보존합니다.

앞으로 기능·수정 단위로 필요한 검증과 개발 노트 갱신을 마친 뒤 한국어 메시지로 커밋하고 원격 저장소에 업로드합니다. 자세한 기준은 [개발 규칙](AGENTS.md#git-기록-규칙)을 따릅니다.

소스, Unity `.meta`·프로젝트 설정, 콘텐츠 원안과 생성된 게임 데이터, 문서, 검증·빌드 스크립트, 글꼴 라이선스를 포함합니다. `android/`와 `prototype/`은 이전 구현 참고용으로 보존합니다. Unity 캐시와 로그, `build/`·`dist/`, 개인 설정과 서명 키, 사용자 제공 참고 이미지는 제외합니다. 설치 파일과 APK는 위 소스로 다시 빌드하며 Git 소스 저장소에는 넣지 않습니다.

## PC 설치 및 업데이트

현재 버전은 **0.18.2**입니다. 거래 수량 줄에 **‘10주’ 선택 버튼을 복원**했습니다. 누르면 주문 수량이 10주로 설정되고, 매수를 반복하면 10주씩 구매합니다. 직접 입력·1주씩 조절·최대 매수·보유 수량 선택도 유지합니다. 차트는 최근 주가 변화가 이어지는 기본 화면 하나이며 갱신 타이머·보유 주식·주문을 함께 보여 줍니다. 종목 목록은 ‘종목 선택’으로 펼칩니다. **물류센터 알바는 내 자산에서 이용**하며 일당 50,000원과 하루 소모 방식은 유지합니다. 실제 Android 기기 검증은 남아 있습니다. 상세 빌드 결과는 [개발 노트](docs/development-log.md)를 확인하세요.

PC에서는 `dist/installer/MoneyTown-0.18.2-Setup-x64.exe`를 실행합니다. 기본 설치 위치는 `%LOCALAPPDATA%\Programs\MoneyTown`이며 관리자 권한 없이 현재 Windows 계정에 설치합니다. 시작 메뉴와 선택한 바탕화면에 바로가기를 만듭니다.

Unity 코어 64개 검사와 480×960·360×800의 격리 UI 검사 각각 115개를 통과했습니다. 저장 형식 9와 기존 거래·정보·알바·결산 규칙은 유지합니다. 기존 30,000원 알바 기록도 보존합니다.

2026-10-14 PC 설치본을 0.18.2로 업데이트했습니다. 설치·재설치에서 배포 파일 144개 일치와 기존 저장·설정 보존을 확인했습니다. 플랫폼별 빌드 결과는 개발 노트에 기록합니다.

다음 업데이트도 게임을 종료하고 새 `MoneyTown-버전-Setup-x64.exe`를 실행하면 됩니다. 이전 설치 위치와 바로가기 선택을 이어서 사용합니다. 인터넷 자동 다운로드는 제공하지 않습니다.

같은 Windows 계정의 기존 PC 저장을 유지합니다. 진행 파일은 `%USERPROFILE%\AppData\LocalLow\MoneyTown\MoneyTown\game-unity-v1.bin`, 게임 설정은 `HKEY_CURRENT_USER\Software\MoneyTown\MoneyTown`에 보관합니다. 설치·업데이트·Windows의 설치된 앱에서 프로그램 제거 시 이 데이터는 삭제하지 않습니다. Unity 에디터 및 Android의 저장은 별개일 수 있습니다.

### 설치 EXE 만들기

Inno Setup 6 이상이 필요합니다. 설치된 컴파일러를 자동 탐색하며, 별도 위치는 `-CompilerPath '경로\ISCC.exe'`로 지정합니다.

```powershell
# Unity 프로젝트 에디터를 닫은 상태에서 Windows 빌드와 설치 EXE를 함께 생성
.\Build-Installer.ps1

# 에디터의 MoneyTown > Build Windows Preview를 실행한 경우
.\Build-Installer.ps1 -SkipUnityBuild

# 실제 현재 계정에 설치·재설치하며 파일 및 기존 저장 보존 검사
.\scripts\Test-Installer.ps1 -InstallerPath .\dist\installer\MoneyTown-0.18.2-Setup-x64.exe
```

Windows는 Development 옵션을 끈 일반 빌드로 생성합니다. 빌드 성공 시 `build-version.txt`를 생성합니다. 패키징은 이 버전과 프로젝트 버전을 대조하며, Windows 플레이어 전체를 설치 파일에 담습니다. 결과 EXE와 SHA-256 파일은 `dist/installer/`에 생성됩니다. 다음 배포에서도 설치 ID `MoneyTown.Unity.Windows`와 사용자별 설치 범위, Unity 회사명·제품명을 유지해야 업데이트와 저장이 이어집니다.

배포 설정은 [windows-installer.iss](packaging/windows-installer.iss)에 있습니다. [Inno Setup의 AppId](https://jrsoftware.org/ishelp/topic_setup_appid.htm)와 [이전 설치 경로 재사용](https://jrsoftware.org/ishelp/topic_setup_usepreviousappdir.htm)을 사용합니다. 현재 설치 EXE에는 코드 서명 인증서를 적용하지 않았습니다.

## Unity 프로젝트 실행

정보와 주가의 연관성은 `dotnet run --project tests/market-correlation/MarketCorrelation.csproj -- 2000 1`로 재현할 수 있습니다. 시드 1~2,000의 12기업, 총 24,000개 사건에서 실제 사건과 개장 방향 일치율은 기존 85.7167%에서 97.3667%로 높아졌습니다. 새 시가는 실제 게임 코어를 사용하고, 기존 시가는 동일 사건·종가·난수의 이전 공식으로 비교했습니다. 이는 정보의 진위나 비용 차감 후 수익률이 아닙니다. [측정 방법](tests/market-correlation/README.md)을 확인하세요.

기준 버전은 **Unity 6000.3.26f1**입니다. Unity Hub에서 이 버전과 Android Build Support, Android SDK & NDK Tools, OpenJDK를 준비하고 Unity 라이선스를 활성화합니다.

1. Unity Hub의 Add 또는 Add project from disk에서 이 저장소의 `unity` 폴더를 선택합니다.
2. 프로젝트를 열고 패키지와 글꼴 가져오기가 끝날 때까지 기다립니다.
3. 상단 메뉴 `MoneyTown > Prepare Project`로 Android 설정을 적용합니다. 기본 씬은 `Assets/Scenes/Main.unity`에 포함되어 있습니다.
4. `Main.unity`를 열고 Play를 누릅니다. Game 뷰를 세로 비율로 설정하면 모바일 구성을 확인할 수 있습니다.
5. `MoneyTown > Run Core Checks`로 규칙을 검증합니다.
6. `MoneyTown > Build Android APK`를 실행합니다. 결과는 `dist/unity/MoneyTown-Unity.apk`입니다.

```powershell
# Unity 없이 거래·저장 규칙 검증 (.NET 10 SDK)
dotnet run --project tests/unity-core/UnityCoreChecks.csproj
# 활성화된 Unity Editor가 있는 경우
.\Build-Unity.ps1 -Target Editor
# 아래 배치 검사·빌드 전에는 이 프로젝트의 에디터를 닫습니다.
.\Build-Unity.ps1 -Target Check
.\Build-Unity.ps1 -Target Android
```

에디터 경로를 자동으로 찾지 못하면 `-UnityPath '설치경로\Editor\Unity.exe'`를 지정합니다. 같은 Unity 프로젝트를 에디터와 배치 빌드에서 동시에 열지 않습니다. Windows 미리보기는 `-Target Windows`로 생성합니다.

이 컴퓨터의 Unity Hub는 Microsoft Store 앱입니다. Hub가 꺼진 상태에서 배치 에디터가 라이선스를 찾지 못하고 종료 코드 198을 반환하면 먼저 설치된 Hub를 정상 실행하고 다시 빌드합니다. 2026-10-12에는 Hub 전용 경로의 기존 라이선스가 정상 갱신되면서 해결됐습니다. 라이선스 파일 삭제·복사나 새 로그인은 필요하지 않았습니다.

이 컴퓨터의 에디터는 `../Tools/Unity/6000.3.26f1/Editor/Unity.exe`에 설치했습니다. Hub에서 버전을 찾지 못하면 **Installs > Locate**로 이 실행 파일을 등록합니다. 기존 Android SDK를 재사용하고, NDK r27c와 Unity 배포 OpenJDK 17은 `../Tools/UnityToolchains/`에 설치했습니다. 이 환경에서 외부 도구 경로를 다시 지정하려면 프로젝트 루트에서 다음을 실행합니다. 경로 설정은 Unity의 External Tools 환경설정에도 저장됩니다.

```powershell
$env:MONEYTOWN_ANDROID_SDK = "$env:LOCALAPPDATA\Android\Sdk"
$env:MONEYTOWN_ANDROID_NDK = (Resolve-Path '..\Tools\UnityToolchains\android-ndk-r27c').Path
$env:MONEYTOWN_ANDROID_JDK = (Resolve-Path '..\Tools\UnityToolchains\OpenJDK').Path
.\Build-Unity.ps1 -Target Android
```

Unity Android 패키지 ID는 `com.moneytown.unity`이며 Android 8.0 이상 ARM64 기기를 대상으로 합니다. GLES3 그래픽을 사용합니다. 기존 Kotlin 앱과 별도로 설치됩니다. 이전 웹 및 Kotlin 저장은 자동 이전하지 않습니다. `dist/MoneyTown-debug.apk`는 이전 Kotlin APK이며 Unity 빌드 결과가 아닙니다.

2026-10-09 Unity Windows 실행 및 Android 개발 APK 빌드를 확인했습니다. APK는 테스트용 서명이며 스토어 배포용 빌드는 아닙니다. 상세 검증 범위와 남은 기기 확인은 개발 노트에 기록합니다. Hub에서 가져오기가 실패하면 `-Target Editor` 명령으로 프로젝트를 직접 열 수 있습니다.

게임 화면은 C#에서 uGUI로 생성합니다. `GameScreen.cs`가 화면과 터치 입력, `PriceChart.cs`가 차트, `MarketIcon.cs`가 자체 제작 벡터 아이콘, `Core/Market.cs`가 경제 규칙을 담당합니다. 안전 영역과 스크롤을 적용했으며 12개 기업의 거래, 뉴스, 보고서, 예금, 간격을 선택하는 장중 시세와 수동 날짜 진행을 제공합니다.

화면은 기업 아이콘, 면적 차트와 하단 고정 거래 패널을 사용합니다. 0.13.0에서는 수량을 직접 입력하거나 `−`, `+`, `최대 매수`, `보유`로 선택합니다. 최대 매수는 반올림 수수료와 거래 한도를 포함합니다. 매수·매도 버튼에 각 방향의 금액 또는 실패 이유를 별도로 표시합니다. 상단 `다음 날 ▶`로 시장을 진행하며, 정보 버튼으로 당일 봉인 정보 가판대를 엽니다. 자산 탭에서는 현금·투자 비중과 예금 만기 게이지를 확인합니다.

0.14.1에서는 하단 주문 영역에 보유 수량을 큰 금색 글씨로 표시합니다. 평균 매수가에는 매수 수수료가 포함되며 소수 둘째 자리까지 표시합니다. 평가손익에는 아직 내지 않은 매도 수수료를 제외합니다. 미보유 종목은 0주, 평균가와 손익은 ‘—’로 표시합니다. 부분·전량 매도 및 다른 종목 선택 시 즉시 갱신합니다.

상단 **간격 설정**에서 시세 갱신 주기를 **30초·1분·3분·5분·15분·30분·1시간**으로 선택합니다. 기본은 30초이며, 선택값은 기기에 자동 저장됩니다. 0.18.0부터 **다음 시세 갱신까지 00:30**은 거래소 차트 위에 한 번만 표시합니다. 1시간 설정에서는 `시:분:초`로 표시하며, 시장이 멈추면 일시정지 상태로 표시합니다.

다른 간격을 선택하면 새 카운트다운을 시작합니다. 같은 간격을 다시 누르면 남은 시간을 유지합니다. 설정 화면을 닫으면 카운트다운이 재개됩니다. 재실행과 다음 날에도 선택한 간격을 유지하며 새 주기부터 시작합니다.

장중 갱신은 날짜와 정보 목록을 유지하고 현재가·차트·평가액·주문 금액만 바꿉니다. 장중 1회 변동은 약 ±0.1~0.6%, ‘다음 날’의 개장 변동은 약 ±1.5~12%입니다. 정수 반올림과 최저가 100원이 적용됩니다.

‘다음 날’을 누르면 **전날 결산**에서 자산 변화, 실현손익, 정보 비용, 수수료, 이자를 확인합니다. 새 하루의 개장 가격과 보유 주식 손익은 별도로 보여줍니다. ‘결산 확인’ 후 시세가 다시 움직이며, 최근 결산은 내 자산에서 다시 읽을 수 있습니다.

앱 비활성·종료·백그라운드·설정·도움말·튜토리얼·결산 중에는 타이머가 멈춥니다. 오프라인 시세를 몰아서 반영하지 않으며 수량 입력과 정보 열람 위치는 장중 갱신 때 유지됩니다. 튜토리얼 v2는 기본 30초 규칙을 가속 체험합니다.

0.9.0에 **10단계 투자 튜토리얼**을 추가했습니다. 처음 실행하면 소개를 표시하며 ‘건너뛰기’가 가능합니다. 별도 연습 자금 100만원으로 1주 매수, 봉인 정보 구매·해석, 다음 날, 매도, 예금 만기를 직접 체험합니다. 본게임 자산과 날짜는 그대로 유지됩니다.

앱을 닫았다 열면 진행 중인 연습을 이어갑니다. ‘나중에’로 나간 경우 **상단 도움말** 또는 **내 자산 > 도움말 · 튜토리얼 다시 보기**에서 이어하거나 처음부터 연습할 수 있습니다. 완료 보상은 없으며 연습을 반복해도 본게임 자금이 늘어나지 않습니다.

0.14.0은 **1~10등급, 등급별 300개씩 총 3,000개 정보 상품**을 제공합니다. 300개 사건 원안을 10단계 취재 깊이로 집필했으며 10등급이 최고입니다. 각 상품에 긍정·부정 판본을 준비했습니다.

- **봉인 정보**: 매일 무작위 9건. 기업·업종·사건·방향은 구매 전 비공개. 등급·매체·가격·신뢰도로 선택합니다.
- **기업 분석**: 기업을 선택해 6·8·10등급 자료를 구매합니다. 기업명·운영 지표·구매 시세·조건을 제시하고 높은 등급은 범위와 반대 시나리오까지 담습니다.
- **내 보관함**: 최근 180건과 이전 버전 구매 자료를 읽습니다. 다음 날 후속 보도로 정보의 사실 여부를 확인합니다.

| 1 | 4,000~6,000원 | 50% | 정체 불명의 정황 |

| 3 | 24,000~36,000원 | 62% | 업종의 주변 단서 |
| 4 | 60,000~90,000원 | 68% | 사건과 업종 |
| 5 | 144,000~216,000원 | 75% | 파급 경로와 근거 |
| 6 | 360,000~540,000원 | 82% | 기업명·운영 지표 |
| 7 | 960,000~1,440,000원 | 88% | 원문·시점·조건 대조 |
| 8 | 2,400,000~3,600,000원 | 93% | 지표 범위·민감도 |
| 9 | 6,000,000~9,000,000원 | 97% | 반대 시나리오 |
| 10 | 16,000,000~24,000,000원 | 99% | 사건 기여도·조건부 시세 범위 |

기업 지정 가격은 봉인 가격의 2배입니다. 6등급 72만~108만원, 8등급 480만~720만원, 10등급 3,200만~4,800만원입니다. 같은 기업의 같은 날 자료는 같은 사건을 다룹니다. **신뢰도는 사건의 사실 여부이며 수익 확률이 아닙니다.**

0.12.0은 **정보 1,000개의 본문을 확장**했습니다. 100개 사건마다 별도로 쓴 현장 묘사·사업 배경·후속 확인 항목을 10등급과 긍정·부정 판본에 반영합니다. 저등급은 누락된 맥락과 제보의 한계를 남기고, 중간 등급은 사건이 사업에 영향을 주는 경로를 설명합니다. 고등급은 기업·운영 지표·실행 조건·반대 시나리오까지 담습니다. 본문은 대략 300~1,500자이며 지면에서 소제목과 문단을 나눠 스크롤로 읽습니다. 구매 전 봉인, 가격과 신뢰도는 유지합니다.

예를 들어 게임박람회 자료는 개최 소식에 더해 체험 대기표, 행사 방문과 이후 결제의 차이, 참가·시연·상담 실적을 읽는 관점을 제공합니다. 등급에 따라 기업명과 지표를 공개하며 특정 종목의 거래를 지시하지 않습니다. 모든 사건은 게임용 창작입니다.

0.12.1은 설명서처럼 들리던 문장을 **매체별 문체**로 교정했습니다. 쪽지·커뮤니티는 전해 들은 말과 첨부 자료를 구분하고, 신문은 사건과 배경을 전하는 기사체, 인터뷰는 문답, 조사·문서·공급망·계약 자료는 각각의 검토 형식으로 읽습니다. 기업 지정 분석은 별도의 보고서 본문을 사용합니다. 사건별 현장 묘사·배경·확인 항목은 유지하고 반복 설명을 줄여 현재 본문은 약 220~1,300자입니다. [같은 사건의 매체별 문체 비교](docs/information-catalog/style-samples.md)를 볼 수 있습니다.

전체 문구는 [등급별 정보 목록](docs/information-catalog/README.md)과 [CSV](docs/information-catalog.csv)에 있습니다. 35개 주제·10개 매체를 사용합니다. `content/information-events.psv`에서 사건 원안, `content/information-dossiers.psv`에서 취재 묘사, `content/information-conversations.psv`에서 구어체 현장 묘사를 편집합니다. `python scripts/build_information_catalog.py`로 게임 카탈로그와 문서를 함께 갱신하고 `python scripts/test_information_catalog.py`로 봉인용 6,000개 판본·기업 지정용 1,800개 본문과 기존 사건·가격의 일관성을 검사합니다. 사건·수치·공개 범위를 변경할 때는 발행판을 올리고 기존 카탈로그를 동결합니다. 0.14.0은 기존 발행판 1·2를 동결하고 확장본을 발행판 3으로 제공합니다. 추가 원안은 `content/expansion-a-*.psv`, `content/expansion-b-*.psv`에 있습니다.

저장은 `Application.persistentDataPath/game-unity-v1.bin`입니다. 0.12 내부 형식은 버전 6이며 1~5의 진행·잔액·주식·예금·구매 자료를 읽습니다. 이전 저장은 필요한 경우 업데이트 당시 자산을 첫 결산 기준으로 사용하며 과거 손익을 만들어내지 않습니다. 결산 미확인 상태와 장중 시세 난수를 보존합니다. 자료는 생성 버전·본문 발행판·지불액·구매 당시 차트까지 보존합니다. 0.8~0.11 구매본은 발행판 1의 당시 문구를 유지합니다. 0.12 구매본은 발행판 2의 확장 본문과 문체 교정을 사용하며 같은 날 기존 구매를 다시 결제하지 않습니다. 체크섬 검증과 임시 파일 교체, 이전 파일의 `.backup`을 사용합니다. 저장 실패 시 행동을 반영하지 않으며 초기화는 확인과 백업을 거칩니다. 새 형식으로 저장한 진행은 이전 게임 버전에서 읽을 수 없으므로 구버전으로 덮어 설치하지 않습니다.

## 0.13.0 소스 개선과 검증

- **복구**: 주 저장이 손상되면 내 자산의 진행 관리에서 검증된 백업의 날짜·총자산을 보고 복구합니다. 복구·초기화 전 주 파일과 백업을 각각 고유한 `.before-recovery-*`, `.before-reset-*` 사본으로 보존합니다. 복구 도중 실패하면 화면 상태를 반영하지 않습니다.
- **정보 구매**: 결제 전에 가격/현재 현금 비율과 구매 후 잔액·부족액을 표시합니다. 기업 분석은 이미 구매한 같은 날·기업의 6등급 이상 자료와 겹치면 경고와 기존 자료 링크를 제공합니다. 봉인 정보의 미공개 기업을 연관 표시로 노출하지 않습니다.
- **기록·목표**: 내 자산에서 최근 거래 100건과 결산 30건을 열람합니다. 최초 거래·실현수익·200만원·세 기업 보유·1천만원 목표를 한 번 달성하면 유지하며 보상은 없습니다. 보유 주식·예금이 없는 자금 부족 상태에는 다음 행동을 안내합니다.
- **차트**: 장중·개장 시세 30개에는 개장 경계를 표시하고, 일별 종가는 실제 결산 30일만 사용합니다. 점 간격은 실시간 간격이 아니며 이전 저장에 없는 날짜를 추정하지 않습니다.
- **저장**: 내부 형식은 **7**, 읽기 호환은 **1~7**입니다. 기존 최신 결산 1건을 보존하며 이전 거래나 시세 날짜를 만들지 않습니다. 기존 잔액·주식·구매본·난수와 결산 대기는 유지됩니다.
- **진단**: [전략 비교 도구](tests/strategy-comparison/README.md)는 현금·장기보유·무작위·유료 정보 전략을 같은 시장에서 비교합니다. 가격·신뢰도·수수료·지원금 정책은 바꾸지 않았습니다.

별도 검증 빌드와 아래 스크립트로 실제 플레이어의 UI 콜백과 렌더링을 검사합니다. 새 임시 저장 폴더와 별도 `MoneyTownVerification` 제품 설정을 사용합니다. 결과 JSON·PNG는 `build/ui-verification-*`에 남깁니다. Windows의 숨긴 창은 렌더링 프레임을 제공하지 않을 수 있어 화면 확인에는 `-Visible`을 사용합니다. 시작 로고가 끝난 뒤 캡처하고 빈 이미지는 실패로 처리합니다. **480×960, 360×800에서 각각 20개 기능 검사가 통과했고 PNG를 확인했습니다.** 자동 콜백 검증은 실제 기기의 터치 검증과 구분합니다.

```powershell
.\Build-Unity.ps1 -Target Verification
.\scripts\Test-UnityUI.ps1 -Visible
.\scripts\Test-UnityUI.ps1 -Width 360 -Height 800 -Visible
dotnet run --project tests/strategy-comparison/StrategyComparison.csproj
```

## 이전 Kotlin 앱 실행

`dist/MoneyTown-debug.apk`를 Android 8.0 이상 기기에 설치합니다. 현재 APK는 개발·테스트용이며 스토어 배포용 서명은 적용하지 않았습니다.

Android Studio에서 `android` 폴더를 열고 SDK 경로를 설정한 뒤 Run으로 실행할 수도 있습니다. 이 컴퓨터에는 기존 Android 개발 환경을 사용했습니다.

```powershell
.\Build-Android.ps1
adb install -r .\dist\MoneyTown-debug.apk
adb shell am start -n com.moneytown.game/.MainActivity
```

여러 기기가 연결됐다면 `adb -s <기기 ID>`로 대상을 지정합니다. 빌드 스크립트는 단위 테스트, APK 빌드와 Lint를 수행한 뒤 `dist`에 APK를 복사합니다. Android SDK 36, JDK 17 도구 체인, Android Studio JBR 및 Gradle 의존성이 필요합니다. `android/local.properties`는 각 컴퓨터의 SDK 경로를 사용하며 버전 관리에서 제외합니다.

주식, 뉴스·정보, 자산의 세 탭을 제공합니다. 기존 6종목 거래, 수수료, 뉴스, 보고서, 예금과 수동 날짜 진행을 Kotlin으로 이식했습니다. 게임은 오프라인으로 동작하며 인터넷 권한을 요청하지 않습니다.

저장은 앱 내부 `files/game-v1.bin`에 수행됩니다. 행동마다 원자적으로 저장한 뒤 화면을 갱신합니다. 손상된 저장은 자동 덮어쓰지 않으며 새 게임 시작 시 기존 파일의 백업을 남깁니다. 앱 삭제 시 내부 저장과 백업도 삭제됩니다. 이전 웹 저장은 자동으로 이전하지 않습니다.

## 기존 웹 프로토타입

`prototype/`과 `android/`는 거래 규칙 비교를 위한 이전 구현입니다. 이후 주 개발 대상은 `unity/`입니다.

`prototype/index.html`을 브라우저로 엽니다. 설치나 빌드 없이 실행됩니다. 6개 종목의 거래, 뉴스, 보고서 구매, 예금, 다음 날 진행과 브라우저 저장을 사용할 수 있습니다.

저장은 현재 브라우저와 실행 주소에 종속됩니다. `file:` 주소의 저장 동작은 브라우저마다 다를 수 있습니다. 안정적인 저장 검증은 아래처럼 프로젝트 폴더에서 HTTP로 실행합니다.

```powershell
python -m http.server 8765 --bind 127.0.0.1
```

브라우저에서 `http://127.0.0.1:8765/prototype/`을 엽니다. 종료는 터미널에서 Ctrl+C를 누릅니다. 저장 오류는 화면에 표시하며 기존 저장을 자동 초기화하지 않습니다.
